# Sunarae — 두벌식 순아래

표준 두벌식 배열에서 모음 반복으로 된소리를 입력하는 작은 macOS 입력기입니다.
키보드 모델이나 펌웨어에 의존하지 않습니다.

**마지막 글자의 선택 표시를 줄이고 Enter를 앱에 전달하는 것**이 이 입력기를 만든 핵심 목적입니다.
일반 조합 방식으로 입력하며, 조합 글자에 표시 속성을 지정하고 커서를 글자 뒤에 둡니다.
Enter는 조합을 확정한 뒤 앱에 전달합니다. 실제 줄바꿈·목록 잇기는 앱의 조합 처리에 따라 다를 수 있습니다.

**개인정보 보호를 최우선으로 설계했습니다.** 입력은 Mac 안에서 처리하며, 입력 내용을 기록하거나 외부로 전송하지 않습니다.
macOS의 입력기 사용 승인 외에 손쉬운 사용·입력 모니터링 등 추가 개인정보 접근 권한을 요구하지 않습니다.
자세한 내용은 [개인정보 보호와 권한](#개인정보-보호와-권한)을 참고하세요.

## 사용

macOS 입력 메뉴에서 **두벌식 순아래**를 선택합니다. 영문은 **ABC**로 전환합니다.
기존 두벌식의 Shift 입력도 사용할 수 있습니다.

| 입력 | 결과 | 실제 키 |
|---|---|---|
| ㄱ + ㅏ + ㅏ | 까 | `rkk` |
| ㄷ + ㅡ + ㅡ + ㅅ | 뜻 | `emmt` |
| ㄱ + ㅗ + ㅗ + ㅐ + ㄱ | 꽥 | `rhhor` |
| ㄱ + ㅓ + ㅓ + ㄱ + ㄱ | 꺾 | `rjjrr` |
| ㅑ + ㅣ / ㅕ + ㅣ | ㅒ / ㅖ | `il` / `ul` |
| ㅇ + ㅕ + ㅣ + ㅅ | 옛 | `dult` |
| 받침 ㄱ + ㄱ / ㅅ + ㅅ | ㄲ / ㅆ | `rr` / `tt` |

받침이 없는 현재 글자에서 같은 모음을 반복하면 초성 ㄱ·ㄷ·ㅂ·ㅅ·ㅈ을 된소리로 바꿉니다.
이미 된소리이거나 바꿀 수 없는 초성이면 모음을 따로 입력합니다. `까+ㅏ→까ㅏ`, `마+ㅏ→마ㅏ`입니다.
초성 자음 반복은 `ㄱㄱ`처럼 그대로 입력합니다. 길게 눌러 생기는 키 반복도 같은 규칙을 따릅니다.

구름 커뮤니티판에서 사용하는 **3beol/libhangul의 `2noshift` 규칙**을 기준으로 삼았습니다.
24키 확장형이 아닙니다. `ㅏ+ㅣ→ㅐ`, `ㅓ+ㅣ→ㅔ`, 역순 모음 결합 등 별도 확장은 넣지 않았습니다.
받침 두 키 뒤에 모음이 오면 첫 자음을 받침으로 남기고 두 번째 자음을 다음 초성으로 넘깁니다.
예를 들어 `ㄱㅏㄱㄱㅏ→각가`, `ㄱㅏㅅㅅㅏ→갓사`입니다.

Backspace는 현재 글자의 마지막 입력을 되돌립니다. `까(rkk)→가→ㄱ→빈칸`입니다.
공백·Enter·방향키·클릭·단축키·입력창 변경은 현재 조합을 끝냅니다.

쉼표와 세미콜론은 일반 문장부호로 입력합니다. 모아치기·한자 변환·약어 기능은 없습니다.

### Esc로 ABC 전환

순아래를 선택한 상태에서 macOS 입력 메뉴의 **Esc / Ctrl+[ 누르면 ABC로 전환**을 체크하면 켜집니다.
기본값은 꺼짐이며, 설정은 앱을 다시 시작해도 유지합니다. 같은 항목을 다시 누르면 꺼집니다.

켜 두면 `Esc` 또는 `Ctrl+[`를 누를 때 현재 글자를 확정하고 macOS에 ABC 전환을 요청합니다.
원래 키는 앱에 넘기므로 Vim의 일반 모드 전환에도 사용합니다.
한글로 돌아갈 때는 기존 한영 전환 키나 아래에서 지정한 키를 사용합니다. 별도의 내부 영문 모드는 없습니다.

Vim 여부와 관계없이 순아래가 키를 받는 모든 앱에 적용합니다. 팝업을 닫는 Esc도 ABC 전환을 요청합니다.
Shift·Option·Command 등을 함께 누른 다른 단축키는 그대로 둡니다.
ABC가 입력 소스 목록에 없거나 전환 요청에 실패하면 한글 입력을 계속할 수 있고 원래 키도 앱에 넘깁니다.
0.3.1에서 사용한 전환 후 키 통과 상태는 제거했습니다. 실제 전환 시점은 macOS와 입력창이 처리합니다.

### Caps Lock으로 한영 전환

macOS의 Caps Lock 전환 옵션과 별개로 순아래에서 켜고 끌 수 있습니다. 기본값은 꺼짐입니다.

1. 순아래를 선택하고 입력 메뉴의 **한영 전환 키 설정…**을 엽니다.
2. **Caps Lock으로 한영 전환**을 체크하고 **적용**을 누릅니다.
3. Caps Lock을 누르면 **ABC ↔ 순아래**로 전환합니다. 한글 조합 중에도 현재 글자를 확정한 뒤 전환합니다.

이 설정은 연결된 키보드의 Caps Lock을 F18로 바꾸고 F18을 순아래 전환 키로 등록합니다.
**손쉬운 사용·입력 모니터링 권한은 필요 없습니다.** 다른 키 입력을 감시하지 않습니다.
켜 둔 동안 Caps Lock의 대문자 고정 기능은 사용할 수 없고, 실제 F18 키도 한영 전환에 쓰입니다.

순아래 자체를 macOS 로그인 항목에 등록해 재부팅 후 로그인할 때 매핑을 다시 적용합니다.
키보드를 새로 연결할 때도 다시 적용합니다. 별도 상주 도우미는 설치하지 않습니다.
macOS가 로그인 항목 승인을 요구하면 창의 **로그인 항목 설정…**에서 순아래 실행을 허용해야 합니다.

체크를 해제하고 **적용**을 누르면 Caps Lock → F18 매핑을 지우고 이전 한영 전환 키를 복원합니다.
이 기능이 추가한 로그인 항목도 해제합니다. 기존에 직접 등록한 로그인 항목과 다른 키 매핑은 유지합니다.
다른 도구가 Caps Lock을 다른 키로 바꾸고 있거나, 기존 글자 키 매핑 때문에 권한 없이 갱신할 수 없으면 변경을 중단하고 알립니다.

이 설정을 끈 상태에서는 macOS의 **시스템 설정 → 키보드 → 텍스트 입력 → 편집 → Caps Lock 키로 ABC 입력 소스 전환**을 사용할 수도 있습니다.
그 방식은 macOS가 전환할 입력 소스를 정하고, 길게 누르면 대문자 고정을 지원합니다.
자세한 내용은 [Apple의 입력 소스 설정 안내](https://support.apple.com/ko-kr/guide/mac-help/-mchl84525d76/mac)를 참고하세요.

### 다른 한영 전환 키 지정

1. 순아래를 선택하고 macOS 입력 메뉴에서 **한영 전환 키 설정…**을 엽니다.
2. **키 입력하기**를 누르고 사용할 키를 누릅니다.
3. 표시된 키를 확인하고 **적용**을 누릅니다. **사용 안 함 → 적용**으로 해제할 수 있습니다.

F1–F20은 단독으로 지정할 수 있고, 일반 키는 Control·Option·Command 중 하나와 조합합니다.
Shift도 함께 넣을 수 있습니다. Caps Lock은 위의 체크 항목을 사용합니다.
이 단축키 지정 기능은 Shift 단독 조합, 수정키 하나만 누르기, Fn 조합을 지원하지 않습니다.
Esc와 Ctrl+[는 위의 ABC 전환 기능에 남겨 둡니다. 키 이름은 두벌식과 같은 QWERTY 위치를 기준으로 표시합니다.

지정한 키는 **순아래 → ABC, ABC 또는 다른 입력기 → 순아래**로 실제 입력 소스를 바꿉니다.
원래 문자나 앱 단축키로는 전달하지 않습니다. 길게 눌러도 한 번만 전환합니다.
설정은 다시 실행해도 유지하며, 기본값은 사용 안 함입니다. 새 키를 입력받는 동안에만 등록을 잠시 해제하고, 입력 완료·취소·창 전환 시 복원합니다.

이미 쓰는 macOS 단축키와 등록 충돌은 알립니다. Karabiner나 키보드 펌웨어에서 바꾸는 키는 모두 감지할 수 없습니다.
다른 도구에서 같은 키를 쓰고 있다면, 순아래에 지정하기 전에 기존 설정을 해제해야 합니다.
Caps Lock 기능을 끈 상태에서는 로그인 후 **순아래를 한 번 선택해 앱을 실행**해야 이 단축키를 받을 수 있습니다.

### 한영 전환 보완

**기본으로 켜져 있습니다.** 한영 표시만 바뀌고 실제 입력 언어가 그대로 남는 현상을 줄이기 위한 기능입니다.
순아래에 지정한 전환 키나 위의 Caps Lock 기능으로 입력 소스를 선택한 뒤,
보이지 않는 작은 패널로 순아래 앱을 잠깐 활성화하고 원래 앱으로 바로 돌아와 입력 연결을 갱신합니다.
고정 대기 시간을 두지 않으며, 다른 앱을 직접 선택하면 이전 앱으로 돌아가도록 강제하지 않습니다.
한글·영문 양방향과 순아래의 Esc / Ctrl+[ 영문 전환에 적용합니다.
macOS 자체 전환 키·입력 메뉴로 전환할 때는 순아래의 전환 함수를 거치지 않아 적용하지 않습니다.

별도 시험에서 실제 전환 누락이 이 방식으로 회복했고, 사용자는 눈에 띄는 창 테두리 깜빡임을 보지 못했습니다.
앱의 활성 상태를 잠깐 바꾸므로 앱에 따라 창 테두리나 포인터가 달라 보일 수 있습니다.
원래 앱으로 돌아오면 패널만 닫으며, 순아래가 활성화되는 동안 포인터가 다시 나타나는 것을 줄이도록 처리합니다.
마우스를 움직이면 포인터가 나타납니다. 다른 앱의 포인터 표시를 강제로 제어하지는 않습니다.
**한영 전환 키 설정… → 한영 전환 보완**에서 체크를 해제하고 **적용**을 누르면 끌 수 있습니다.
직접 꺼 둔 설정은 업데이트와 다음 실행에서도 유지합니다.
추가 권한, 네트워크 통신, 입력 내용 기록은 없습니다.

## 설치·업데이트·삭제

1. [Releases](https://github.com/astrod/Sunarae-keymap/releases)에서 `Sunarae-버전-arm64.pkg`를 내려받아 엽니다. 배포 파일은 Apple Silicon용입니다.
2. macOS 기본 **설치 프로그램**에서 현재 사용자용으로 설치합니다. 별도 설치 앱이나 터미널 명령은 필요 없습니다.
3. 입력 메뉴에서 **두벌식 순아래**를 선택하고 macOS의 사용 승인 요청을 직접 확인합니다.

설치 파일은 아직 Developer ID 서명·공증을 받지 않았습니다. macOS가 실행을 막으면 시스템 설정의 개인정보 보호 및 보안에서 출처를 확인하고 직접 허용해야 할 수 있습니다.

설치 도구는 사용 중인 순아래를 ABC로 전환한 뒤 `~/Library/Input Methods/Sunarae.app`을 교체합니다.
ABC 전환이나 현재 입력기 확인에 실패하면 기존 앱을 보존하고 중단합니다. 관리자 권한은 쓰지 않습니다.
입력 메뉴에 보이지 않으면 로그아웃 후 다시 로그인하고 **시스템 설정 → 키보드 → 텍스트 입력 → 편집**에서 추가합니다.
설치·업데이트 직후 영문만 나오면 다른 입력기로 바꿨다가 순아래를 다시 선택합니다.
특정 앱에서 계속 영문이 나오면 작성 중인 내용을 보관하고 그 앱을 완전히 종료한 뒤 다시 엽니다.
0.6.0부터 모든 앱에서 일반 조합과 표시 속성 지정을 사용합니다. 이전의 확정 글자 교체·문서 조회·지연 복구 코드는 제거했습니다. 배포 여부와 내려받을 수 있는 버전은 Releases에서 확인하세요.

0.5.1에서 보완한 전환 아이콘 표시도 포함합니다. 업데이트 뒤에도 표시가 비어 있으면 macOS가 이전 표시 정보를 유지할 수 있어, 로그아웃 후 다시 로그인해야 할 수 있습니다.

내부 등록 ID는 `local.inputmethod.Sunarae`입니다. 설치 위치에 등록 ID가 다른 순아래가 있으면 앱 정보를 확인해 이전 입력 소스를 해제하고 새 ID로 등록합니다.
이 경우 새 입력기 사용 승인과 Esc·한영 전환 키 설정이 한 번 필요합니다. 이후 같은 ID로 업데이트하면 설정을 유지합니다.

소스에서 설치하려면 `make build` 후 `dist/Install.command`를 실행해도 됩니다. 이 경로에서는 먼저 다른 입력기를 선택합니다.
삭제는 Releases의 **`Sunarae-버전-uninstall-arm64.zip`**을 내려받아 압축을 푼 뒤 할 수 있습니다.
입력기를 ABC 또는 다른 입력기로 바꾸고, 압축을 푼 폴더의 **`Uninstall.command`**를 실행하세요.
같은 폴더의 `Support`도 필요하므로 `Uninstall.command`만 따로 옮기지 마세요. 소스에서 빌드했다면 `dist/Uninstall.command`를 사용할 수 있습니다.
삭제 도구는 입력 소스와 Caps Lock 설정·이 기능이 추가한 로그인 항목을 해제하고 앱을 휴지통으로 옮깁니다.
설정 정리에 실패하면 앱을 지우지 않고 중단합니다. 다른 키 매핑과 기존 로그인 항목은 유지합니다.
직접 삭제할 때는 먼저 순아래 설정에서 Caps Lock 기능을 끄고 적용하세요. 그 뒤 입력 소스 목록에서 순아래를 제거하고 로그아웃한 다음 `~/Library/Input Methods/Sunarae.app`을 휴지통으로 옮깁니다.

문제가 생기면 소스 폴더에서 `make diagnose`를 실행합니다. 버전·서명·등록 상태만 읽고 입력 내용이나 클립보드는 읽지 않습니다.
Intel Mac은 소스에서 직접 빌드할 수 있지만 실제 실행 검증은 하지 않았습니다.

## 앱에 글자를 전달하는 방식

`ㄱ→가→까`는 앱의 조합 영역에서 갱신하고, 음절이 끝날 때 확정합니다.
조합 글자는 밑줄과 배경 표시를 없애도록 요청하고, 선택 길이 0인 커서를 끝에 둡니다.
이미 확정된 글자를 찾아 교체하거나 지우지 않으며, 앱별로 다른 전달 방식을 선택하지 않습니다.

Backspace는 현재 조합을 한 키씩 되돌립니다. 조합이 끝난 글자의 삭제는 앱이 처리합니다.
Enter·Space·Tab·문장부호·이동 키·단축키는 조합을 한 번 확정한 뒤 원래 키를 앱에 전달합니다.
앱이 조합을 취소하거나 입력창이 바뀌면 이전 조합을 새 문서에 복원하지 않습니다.

선택 표시와 Enter 동작은 앱의 조합 처리에도 영향을 받습니다. 표시 속성을 지정해도 웹 편집기는
조합 갱신 중 잠깐 선택 범위를 만들 수 있고, 일부 편집기는 첫 Enter를 조합 확정으로 처리할 수 있습니다.
입력기는 이를 우회하려고 Enter를 다시 보내거나 줄바꿈을 직접 삽입하지 않습니다.

## 빌드·검사

Swift와 C(libhangul)를 사용합니다. Xcode Command Line Tools가 필요하며, 일반 빌드는 네트워크나 패키지 관리자를 쓰지 않습니다. 아래 명령은 소스 프로젝트의 루트 폴더에서 실행합니다.

```sh
git clone https://github.com/astrod/Sunarae-keymap.git
cd Sunarae-keymap
```

```sh
make build    # 앱 빌드
make package  # macOS 기본 설치 프로그램용 .pkg 만들기
make test     # 조합·편집 검사
make check    # 규칙 확인 + 빌드 + 조합·편집·설치 검사 + 앱 자체 검사
```

`make`만 실행하면 명령 목록을 보여 줍니다. `make check`의 규칙 확인에는 Python 3가 필요합니다.
기존 `scripts/build.sh`, `scripts/test.sh`도 계속 사용할 수 있습니다.
검사 스크립트는 C 라이브러리를 매번 새로 빌드하므로, 처음 실행하거나 C 코드를 고친 뒤에도 현재 코드로 검사합니다.
개발 설정은 `scripts/build-common.sh`에 모았습니다. [코드 관리 안내](CONTRIBUTING.md)에 수정할 파일과 확인 절차를 정리했습니다.
빌드는 임시 폴더에서 앱·설치 도구의 서명과 파일 준비를 마친 뒤 `dist` 전체를 교체합니다.
빌드 실패 시 이전 `dist`를 보존하며, 정상 교체 시 오래된 결과물이 남지 않습니다.
`make packaging`으로 설치·빌드 실패 검사만 실행할 수도 있습니다. 임시 폴더와 등록 도구 대역을 사용하며 실제 입력기를 등록하거나 선택하지 않습니다.

`--self-check`는 고정 예문과 로컬 루프백 주소로 조합·샌드박스의 네트워크 차단을 확인합니다.
`Tests`는 현대 한글 11,172자 각각의 일반 두벌식/순아래 입력과 모든 키의 되돌리기, 실제 NSTextView에서의 삽입·삭제·커서·재진입을 검사합니다.

실제 키 입력 시험창은 다음과 같이 만듭니다. 웹 검사에만 Node.js/npm이 필요합니다.
시험창은 다른 앱의 문서나 입력을 읽지 않지만, 그 창에 입력한 내용과 입력 이벤트를 `build/input-probe.jsonl`에 기록합니다.
고정 예문으로만 시험하세요. 이 시험 앱은 배포용 입력기에 포함하지 않습니다.

```sh
make probe       # 네이티브 시험창 빌드
make web-probe   # 시험창 + CodeMirror 빌드
```

[현재 구현](docs/IMPLEMENTATION.md)에 전달 방식과 확인 범위를 적었습니다. `docs/INPUT-VERIFICATION-*.md`는 해당 과거 버전의 검사 기록입니다.

## 개인정보 보호와 권한

이 설명은 배포용 `Sunarae.app`의 동작을 기준으로 합니다.

### 데이터 처리

- **입력 내용을 기록하지 않습니다.** 파일·설정·로그에 입력 내용을 남기지 않으며, 입력 기록이나 사용 통계를 수집하지 않습니다.
- **외부 네트워크 전송이 없습니다.** 한글 조합은 Mac 안에서 처리하며, 분석·원격 오류 보고·자동 업데이트 기능이 없습니다.
  앱은 네트워크 송수신 권한 없이 App Sandbox에서 실행합니다.
- **조합에 필요한 내용만 메모리에서 처리합니다.** 현재 조합과 한 키씩 되돌리기 상태를 보관하고, 앱의 조합 영역이 유지되는지 확인합니다.
  문서의 글자나 커서 위치를 조회하지 않으며, 조합 종료 시 상태를 비웁니다.
- **로컬 설정에는 사용자가 정한 값만 저장합니다.** Esc 전환 여부, 한영 전환 키, 한영 전환 보완 여부, Caps Lock 설정과 해제 시 복원할 이전 키, 이 기능이 로그인 항목을 추가했는지를 저장합니다.
  전역 단축키는 지정한 조합 하나만 macOS에 등록하며, 설정 창에서 키를 지정할 때는 그 창의 키 입력만 받습니다.
  Caps Lock 기능은 키 매핑 속성과 키보드 연결 여부만 다룹니다. 전체 키 입력을 감시하는 기능은 없습니다.
  한영 전환 보완은 전환 중 현재 입력 소스와 활성 앱의 번호를 확인합니다.
  포인터 위치는 전환 전에 한 번, 순아래 활성화 시 한 번 확인해 사용자가 움직인 포인터를 다시 숨기지 않도록 합니다.
  이 위치는 메모리에서만 비교하고 전환이 끝나면 버립니다. 앱 사용 내역이나 마우스 이동 기록은 저장하지 않습니다.
- **진단·오류 로그에는 입력 내용을 넣지 않습니다.** 검사 결과나 입력 소스 전환 실패 상태만 남깁니다.

저장하는 설정은 [`Sources/InputSettings.swift`](Sources/InputSettings.swift)에서 확인할 수 있습니다.

### 필요한 권한과 승인

| 항목 | 필요 여부 | 설명 |
|---|---|---|
| macOS 입력기 사용 승인 | 필요 | 새 입력기를 처음 사용할 때 macOS가 표시하는 사용 승인입니다. |
| 설치 파일·앱 실행 허용 | 표시되는 경우 필요 | 현재 배포 파일은 Developer ID 서명·공증을 받지 않았으므로 macOS가 실행 허용을 요구할 수 있습니다. |
| 로그인 시 실행 승인 | Caps Lock 기능 사용 시 | 재부팅 뒤 매핑을 적용하기 위해 순아래를 로그인 항목에 등록합니다. macOS 설정에서 승인이 필요할 수 있습니다. |
| 손쉬운 사용·입력 모니터링 | 불필요 | 권한을 요청하지 않습니다. 지정한 한영 전환 키도 별도 입력 모니터링 권한 없이 등록합니다. |
| 전체 디스크 접근·화면 기록·다른 앱 자동화 | 불필요 | 권한을 요청하지 않습니다. |
| 관리자 권한 | 불필요 | 현재 사용자의 `~/Library/Input Methods`에 설치합니다. |

입력기 사용 승인과 실행 허용은 추가 개인정보 접근 권한과 별개입니다.

권한 설정은 [`Resources/Sunarae.entitlements`](Resources/Sunarae.entitlements)에서 확인할 수 있습니다.
입력기 연결과 입력 소스 전환에 필요한 macOS 내부 통신만 허용하며, 네트워크 송수신 권한은 부여하지 않습니다.

### 개발용 검사와 시험창

개발자가 명시적으로 실행하는 `--self-check`에만 네트워크 차단 검사용 연결 시도가 있습니다.
외부 서버가 아닌 이 Mac의 `127.0.0.1:9`에 접속을 시도하고, 샌드박스가 이를 거부하는지 확인합니다.
입력 내용을 보내지 않으며 평소 입력 중에는 이 검사를 실행하지 않습니다.

별도 개발용 시험창 `InputProbe.app`은 그 창에 입력한 내용과 입력 이벤트를 `build/input-probe.jsonl`에 기록합니다.
이 파일은 로컬에만 저장하며, 시험창은 배포용 입력기에 포함하지 않습니다.
자세한 실행 방법은 위의 [빌드·검사](#빌드검사)에 설명했습니다.

## 소스

- `Sources/Composer.swift`: 순아래 조합 엔진과 한 키씩 되돌리기.
- `Sources/KeyMap.swift`: macOS 키 위치와 Shift 해석.
- `Sources/InputSession.swift`: 키 처리, 확정, 중첩 호출 방지.
- `Sources/InputSettings.swift`, `Sources/InputSource.swift`: Esc 전환 설정과 macOS ABC 선택 요청.
- `Sources/KeyboardShortcut.swift`, `Sources/GlobalHotKey.swift`, `Sources/ShortcutManager.swift`: 한영 전환 키 검증·등록·저장과 실제 입력 소스 전환.
- `Sources/InputSourceFocusRefresh.swift`: 패널을 통한 앱 활성화·복귀와 종료·취소 처리.
- `Sources/CapsLockMapping.swift`, `Sources/KeyboardConnectionObserver.swift`: Caps Lock 매핑·복원, 로그인 시 실행, 새 키보드 연결 처리.
- `Sources/ShortcutSettingsController.swift`: 키 지정·변경·해제 창.
- `Sources/TextClient.swift`, `Sources/InputController.swift`: 앱의 텍스트 API와 InputMethodKit 연결.
- `vendor/libhangul/`: 고정한 한글 엔진과 순아래 변경 사항.
- `spec/`: 순아래 규칙과 출처.

순아래 제작자는 **꼬마집오리**입니다. [제작자 설명](https://sites.google.com/site/tinyduckn/dubeolsig-sun-alae),
[구현 기준](https://github.com/3beol/libhangul/blob/5244cb30b0f995ff2567ab2ac51dba3e9958a0d2/data/keyboards_info/2set_2noshift.txt),
