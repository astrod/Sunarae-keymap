# Sunarae — 두벌식 순아래

표준 두벌식 배열에서 모음 반복으로 된소리를 입력하는 작은 macOS 입력기입니다.
키보드 모델이나 펌웨어에 의존하지 않습니다.

SilverBullet용으로 만든 **마지막 글자를 일반 텍스트로 바로 표시하는 처리**를 유지합니다.
앱이 문서 접근을 지원하면 조합 표시를 남기지 않고 글자를 교체하며, Enter는 앱에 바로 넘깁니다.

## 사용

macOS 입력 메뉴에서 **두벌식 순아래**를 선택합니다. 영문은 **ABC**로 전환합니다.
기존 두벌식의 Shift 입력도 사용할 수 있습니다.

| 입력 | 결과 | 실제 키 |
|---|---|---|
| ㄱ + ㅏ + ㅏ | 까 | `rkk` |
| ㄷ + ㅡ + ㅡ + ㅅ | 뜻 | `emmt` |
| ㄱ + ㅗ + ㅗ + ㅐ + ㄱ | 꽥 | `rhhor` |
| ㄱ + ㅓ + ㅓ + ㄱ + ㄱ | 꺾 | `rjjrr` |
| ㅑ + ㅣ / ㅕ + ㅣ | ㅒ / ㅖ | `il` / `ul` |
| ㅇ + ㅕ + ㅣ + ㅅ | 옛 | `dult` |
| 받침 ㄱ + ㄱ / ㅅ + ㅅ | ㄲ / ㅆ | `rr` / `tt` |

받침이 없는 현재 글자에서 같은 모음을 반복하면 초성 ㄱ·ㄷ·ㅂ·ㅅ·ㅈ을 된소리로 바꿉니다.
이미 된소리이거나 바꿀 수 없는 초성이면 모음을 따로 입력합니다. `까+ㅏ→까ㅏ`, `마+ㅏ→마ㅏ`입니다.
초성 자음 반복은 `ㄱㄱ`처럼 그대로 입력합니다. 길게 눌러 생기는 키 반복도 같은 규칙을 따릅니다.

구름 커뮤니티판에서 사용하는 **3beol/libhangul의 `2noshift` 규칙**을 기준으로 삼았습니다.
24키 확장형이 아닙니다. `ㅏ+ㅣ→ㅐ`, `ㅓ+ㅣ→ㅔ`, 역순 모음 결합 등 별도 확장은 넣지 않았습니다.
받침 두 키 뒤에 모음이 오면 첫 자음을 받침으로 남기고 두 번째 자음을 다음 초성으로 넘깁니다.
예를 들어 `ㄱㅏㄱㄱㅏ→각가`, `ㄱㅏㅅㅅㅏ→갓사`입니다.

Backspace는 현재 글자의 마지막 입력을 되돌립니다. `까(rkk)→가→ㄱ→빈칸`입니다.
공백·Enter·방향키·클릭·단축키·입력창 변경은 현재 조합을 끝냅니다.

쉼표와 세미콜론은 일반 문장부호로 입력합니다. 모아치기·한자 변환·약어 기능은 없습니다.

### Esc로 ABC 전환

순아래를 선택한 상태에서 macOS 입력 메뉴의 **Esc / Ctrl+[ 누르면 ABC로 전환**을 체크하면 켜집니다.
기본값은 꺼짐이며, 설정은 앱을 다시 시작해도 유지합니다. 같은 항목을 다시 누르면 꺼집니다.

켜 두면 `Esc` 또는 `Ctrl+[`를 누를 때 현재 글자를 확정하고 macOS에 ABC 전환을 요청합니다.
원래 키는 앱에 넘기므로 Vim의 일반 모드 전환에도 사용합니다.
한글로 돌아갈 때는 기존 한영 전환 키나 아래에서 지정한 키를 사용합니다. 별도의 내부 영문 모드는 없습니다.

Vim 여부와 관계없이 순아래가 키를 받는 모든 앱에 적용합니다. 팝업을 닫는 Esc도 ABC 전환을 요청합니다.
Shift·Option·Command 등을 함께 누른 다른 단축키는 그대로 둡니다.
ABC가 입력 소스 목록에 없거나 전환 요청에 실패하면 한글 입력을 계속할 수 있고 원래 키도 앱에 넘깁니다.
0.3.1에서 사용한 전환 후 키 통과 상태는 제거했습니다. 실제 전환 시점은 macOS와 입력창이 처리합니다.

### 한영 전환 키 지정

1. 순아래를 선택하고 macOS 입력 메뉴에서 **한영 전환 키 설정…**을 엽니다.
2. **키 입력하기**를 누르고 사용할 키를 누릅니다.
3. 표시된 키를 확인하고 **적용**을 누릅니다. **사용 안 함 → 적용**으로 해제할 수 있습니다.

F1–F20은 단독으로 지정할 수 있고, 일반 키는 Control·Option·Command 중 하나와 조합합니다.
Shift도 함께 넣을 수 있습니다. Shift 단독 조합, 수정키 하나만 누르기, Fn 조합은 지원하지 않습니다.
Esc와 Ctrl+[는 위의 ABC 전환 기능에 남겨 둡니다. 키 이름은 두벌식과 같은 QWERTY 위치를 기준으로 표시합니다.

지정한 키는 **순아래 → ABC, ABC 또는 다른 입력기 → 순아래**로 실제 입력 소스를 바꿉니다.
원래 문자나 앱 단축키로는 전달하지 않습니다. 길게 눌러도 한 번만 전환합니다.
설정은 다시 실행해도 유지하며, 기본값은 사용 안 함입니다. 설정 창을 열어 둔 동안에는 등록을 잠시 해제합니다.

이미 쓰는 macOS 단축키와 등록 충돌은 알립니다. Karabiner나 키보드 펌웨어에서 바꾸는 키는 모두 감지할 수 없습니다.
다른 도구에서 같은 키를 쓰고 있다면, 순아래에 지정하기 전에 기존 설정을 해제해야 합니다.
로그인 직후에는 **순아래를 한 번 선택해 앱을 실행**해야 이 단축키를 받을 수 있습니다.
별도 로그인 항목이나 상주 도우미는 추가하지 않습니다.

## 설치·업데이트·삭제

1. [Releases](https://github.com/astrod/Sunarae-keymap/releases)에서 `Sunarae-버전-arm64.pkg`를 내려받아 엽니다. 배포 파일은 Apple Silicon용입니다.
2. macOS 기본 **설치 프로그램**에서 현재 사용자용으로 설치합니다. 별도 설치 앱이나 터미널 명령은 필요 없습니다.
3. 입력 메뉴에서 **두벌식 순아래**를 선택하고 macOS의 사용 승인 요청을 직접 확인합니다.

설치 파일은 아직 Developer ID 서명·공증을 받지 않았습니다. macOS가 실행을 막으면 시스템 설정의 개인정보 보호 및 보안에서 출처를 확인하고 직접 허용해야 할 수 있습니다.

설치 도구는 사용 중인 순아래를 ABC로 전환한 뒤 `~/Library/Input Methods/Sunarae.app`을 교체합니다.
ABC 전환이나 현재 입력기 확인에 실패하면 기존 앱을 보존하고 중단합니다. 관리자 권한은 쓰지 않습니다.
입력 메뉴에 보이지 않으면 로그아웃 후 다시 로그인하고 **시스템 설정 → 키보드 → 텍스트 입력 → 편집**에서 추가합니다.
설치·업데이트 직후 영문만 나오면 다른 입력기로 바꿨다가 순아래를 다시 선택합니다.
특정 앱에서 계속 영문이 나오면 작성 중인 내용을 보관하고 그 앱을 완전히 종료한 뒤 다시 엽니다.
0.5.5는 조회 실패 뒤 오래된 응답 때문에 보류한 키를 버리던 경우를 고쳤습니다. 글자와 커서를 다시 확인해 맞으면 조합을 이어가고, 실제 변경을 확인하거나 끝까지 확인하지 못하면 다른 내용을 덮어쓰지 않습니다. 마지막 글자의 조합 표시 없는 입력과 Enter 전달, Ghostty 호환성은 유지합니다. 모든 원인의 간헐적 입력 오류를 해결한 것은 아닙니다.

0.5.1에서 보완한 전환 아이콘 표시도 포함합니다. 업데이트 뒤에도 표시가 비어 있으면 macOS가 이전 표시 정보를 유지할 수 있어, 로그아웃 후 다시 로그인해야 할 수 있습니다.

내부 등록 ID는 `local.inputmethod.Sunarae`입니다. 설치 위치에 등록 ID가 다른 순아래가 있으면 앱 정보를 확인해 이전 입력 소스를 해제하고 새 ID로 등록합니다.
이 경우 새 입력기 사용 승인과 Esc·한영 전환 키 설정이 한 번 필요합니다. 이후 같은 ID로 업데이트하면 설정을 유지합니다.

소스에서 설치하려면 `make build` 후 `dist/Install.command`를 실행해도 됩니다. 이 경로에서는 먼저 다른 입력기를 선택합니다.
삭제는 다른 입력기를 선택한 뒤 `dist/Uninstall.command`로 할 수 있습니다. 입력 소스를 해제하고 앱을 휴지통으로 옮깁니다.
패키지로만 설치했다면 입력 소스 목록에서 순아래를 제거하고 로그아웃한 뒤 `~/Library/Input Methods/Sunarae.app`을 휴지통으로 옮깁니다.

문제가 생기면 소스 폴더에서 `make diagnose`를 실행합니다. 버전·서명·등록 상태만 읽고 입력 내용이나 클립보드는 읽지 않습니다.
Intel Mac은 소스에서 직접 빌드할 수 있지만 실제 실행 검증은 하지 않았습니다.

## 앱에 글자를 전달하는 방식

문서 접근을 지원하는 앱에는 `ㄱ→가→까`를 일반 텍스트로 바로 삽입·교체합니다.
교체 전에는 커서 위치와 해당 글자가 그대로인지 확인합니다. 처음 삽입할 때는 앱의 현재 선택 영역을 사용합니다.
이미 반영한 글자는 Enter를 누를 때 다시 보내지 않습니다. 일시적인 조회 실패로 보류한 입력이 있으면 먼저 처리한 뒤 Enter를 앱에 넘깁니다. 그래서 편집기가 Enter로 목록을 이어 쓸 수 있습니다.

앱이 글자나 커서 정보를 잠깐 돌려주지 않으면 다음 한글 입력을 보관하고 짧은 간격으로 다시 확인합니다. 원래 글자와 커서가 맞으면 조합을 이어갑니다. 문서나 커서가 바뀌면 이전에 보류한 입력을 취소해 새 위치에 뒤늦게 쓰지 않습니다. 조회가 계속 실패하면 기다림을 끝내며 자모가 분리될 수 있습니다.

이전 버전의 연속 삭제 수정도 유지합니다. 입력기가 방금 쓴 글자를 지울 때에는 삭제도 문자 전달 경로에서 처리해,
마지막 Backspace가 다음 입력보다 늦게 적용되지 않도록 합니다. 외부 편집·커서 이동 뒤에는 이전 글자를 지우지 않습니다.

문서 접근을 제공하지 않는 앱과 Ghostty에서는 일반 조합 표시 방식으로 돌아갑니다. 그 앱에서는 마지막 글자와 Enter의 동작이 다를 수 있습니다.
앱별 호환성을 모두 보장하는 방식은 아닙니다.

## 빌드·검사

Swift와 C(libhangul)를 사용합니다. Xcode Command Line Tools가 필요하며, 일반 빌드는 네트워크나 패키지 관리자를 쓰지 않습니다. 아래 명령은 소스 프로젝트의 루트 폴더에서 실행합니다.

```sh
git clone https://github.com/astrod/Sunarae-keymap.git
cd Sunarae-keymap
```

```sh
make build    # 앱 빌드
make package  # macOS 기본 설치 프로그램용 .pkg 만들기
make test     # 조합·편집 검사
make check    # 규칙 확인 + 빌드 + 조합·편집·설치 검사 + 앱 자체 검사
```

`make`만 실행하면 명령 목록을 보여 줍니다. `make check`의 규칙 확인에는 Python 3가 필요합니다.
기존 `scripts/build.sh`, `scripts/test.sh`도 계속 사용할 수 있습니다.
검사 스크립트는 C 라이브러리를 매번 새로 빌드하므로, 처음 실행하거나 C 코드를 고친 뒤에도 현재 코드로 검사합니다.
개발 설정은 `scripts/build-common.sh`에 모았습니다. [코드 관리 안내](CONTRIBUTING.md)에 수정할 파일과 확인 절차를 정리했습니다.
빌드는 임시 폴더에서 앱·설치 도구의 서명과 파일 준비를 마친 뒤 `dist` 전체를 교체합니다.
빌드 실패 시 이전 `dist`를 보존하며, 정상 교체 시 오래된 결과물이 남지 않습니다.
`make packaging`으로 설치·빌드 실패 검사만 실행할 수도 있습니다. 임시 폴더와 등록 도구 대역을 사용하며 실제 입력기를 등록하거나 선택하지 않습니다.

`--self-check`는 고정 예문과 로컬 루프백 주소로 조합·샌드박스의 네트워크 차단을 확인합니다.
`Tests`는 현대 한글 11,172자 각각의 일반 두벌식/순아래 입력과 모든 키의 되돌리기, 실제 NSTextView에서의 삽입·삭제·커서·재진입을 검사합니다.

실제 키 입력 시험창은 다음과 같이 만듭니다. 웹 검사에만 Node.js/npm이 필요합니다.
시험창은 다른 앱의 문서나 입력을 읽지 않고, 그 창에 입력한 고정 예문만 `build/input-probe.jsonl`에 기록합니다.

```sh
make probe       # 네이티브 시험창 빌드
make web-probe   # 시험창 + CodeMirror 빌드
```

[검증 기록](docs/INPUT-VERIFICATION-DEFERRED-VALIDATION.md)에 검사 결과와 확인 범위를 적었습니다.

## 소스·개인정보

- `Sources/Composer.swift`: 순아래 조합 엔진과 한 키씩 되돌리기.
- `Sources/KeyMap.swift`: macOS 키 위치와 Shift 해석.
- `Sources/InputSession.swift`: 키 처리, 확정, 중첩 호출 방지.
- `Sources/InputSettings.swift`, `Sources/InputSource.swift`: Esc 전환 설정과 macOS ABC 선택 요청.
- `Sources/KeyboardShortcut.swift`, `Sources/GlobalHotKey.swift`, `Sources/ShortcutManager.swift`: 한영 전환 키 검증·등록·저장과 실제 입력 소스 전환.
- `Sources/ShortcutSettingsController.swift`: 키 지정·변경·해제 창.
- `Sources/TextDelivery.swift`: 커서·문자 확인, 직접 삽입·교체·삭제, 조합 표시 방식으로 전환.
- `Sources/TextClient.swift`, `Sources/InputController.swift`: 앱의 텍스트 API와 InputMethodKit 연결.
- `vendor/libhangul/`: 고정한 한글 엔진과 순아래 변경 사항.
- `spec/`: 순아래 규칙과 출처.

입력 내용 저장·전송·분석·자동 업데이트 기능이 없습니다. 앱은 네트워크 권한 없이 App Sandbox를 사용합니다.
손쉬운 사용·입력 모니터링 권한을 요구하지 않습니다. 현재 글자와 연속 삭제에 필요한 상태만 메모리에 두고 조합 종료 시 비웁니다.
전역 단축키는 지정한 조합 하나만 macOS에 등록합니다. 키를 지정할 때는 설정 창의 입력만 받으며, 설정한 키와 수정키만 저장합니다.

순아래 제작자는 **꼬마집오리**입니다. [제작자 설명](https://sites.google.com/site/tinyduckn/dubeolsig-sun-alae),

## 라이선스

직접 작성한 Swift 앱·스크립트·테스트 코드는 [MIT](LICENSE)입니다. 저작권과 라이선스 고지를 유지하면 수정·재배포·상업적 이용이 가능합니다.

함께 포함한 파일에는 각 원본 라이선스가 적용됩니다.

- libhangul, 수정한 한글 엔진, 순아래 규칙과 참고 자료: [LGPL-2.1-or-later](vendor/libhangul/COPYING).

앱은 libhangul을 정적으로 연결합니다. 이 프로젝트의 실행 파일은 해당 버전의 전체 앱·라이브러리 소스, 빌드 스크립트와 라이선스 고지를 함께 제공하는 방식으로 배포합니다. 수정한 라이브러리로 다시 빌드할 수 있도록 하기 위해서입니다. 자세한 출처와 배포 조건은 [THIRD_PARTY.md](THIRD_PARTY.md)에 정리했습니다.
