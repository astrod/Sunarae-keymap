## 확인한 문제

### P2: 등록 목록 갱신이 늦으면 첫 설치한 앱을 삭제한다

- 위치: `scripts/InputSourceTool.swift:38`, `scripts/install.sh:38–46,62–63`.
- 조건: Launch Services와 TIS 등록은 성공했지만 곧바로 읽은 입력 소스 목록이 비어 있다.
- 도구는 로그아웃 후 다시 로그인하라는 안내와 함께 실패 코드로 종료한다. 설치 스크립트는 이를 등록 실패로 처리해 새 앱을 지운다. 첫 설치라면 복구할 이전 앱도 없으므로 다시 로그인해도 설치할 앱이 남지 않는다.
- 재현: 임시 설치 폴더와 등록 도구 대역을 사용했다. 등록 목록 지연에 해당하는 실패를 반환하면 첫 설치의 앱이 사라졌다. 업데이트에서는 이전 앱을 복원했다. 실제 macOS 등록을 바꾸거나 목록 지연을 강제로 일으킨 검사는 아니다.
- 수정 방향: 등록 실패와 등록 후 목록 갱신 대기를 구분한다. 등록 성공 후 목록 갱신을 기다리는 상태에는 앱을 보존하고 후속 추가·로그인 절차를 안내한다. 실제 등록 실패에는 기존 복원 절차를 유지한다. 이 두 결과를 설치 검사에 포함한다.

## 정리할 만한 부분

1. **완성한 빌드 결과만 교체하기** — `scripts/build.sh:4–19`는 기존 `dist/Sunarae.app`에 실행 파일과 자료를 차례로 덮어쓴다. 중간 단계가 실패하면 개발용 결과물이 부분 갱신 상태로 남을 수 있고, 더 이상 복사하지 않는 옛 자료도 남는다. 새 임시 폴더에서 빌드·서명·검증을 마친 뒤 결과물을 교체하면 관리하기 쉽다. 현재 설치된 앱에 영향을 주는 문제는 아니다.
2. **사용하지 않는 인자 제거** — `Sources/InputSession.swift:34`의 `isRepeat`는 전달만 받고 읽지 않는다. 현재 정책은 자동 키 반복과 개별 키 입력을 같게 처리하므로 인자를 제거해도 그 정책은 유지된다. 호출부와 검사도 함께 정리한다. 속도 개선을 기대할 항목은 아니다.
3. **변경 이력 관리** — 이 폴더에는 Git 저장소가 없고 백업 압축 파일로 이전 상태를 보관한다. 정상 버전부터 Git 이력을 남기면 수정 비교와 복구가 쉬워진다. 현재 입력 동작과 별개인 관리 제안이다.

조합, 앱에 글자 전달, InputMethodKit 연결은 이미 다른 파일로 나뉘어 있다. 더 잘게 나누거나 한 번에 다시 작성할 근거는 찾지 못했다. 특히 커서·문자 확인과 중첩 호출 방지는 이전 호환성 문제를 막는 코드이므로 단순히 호출 수를 줄이기 위해 제거하지 않는다.
