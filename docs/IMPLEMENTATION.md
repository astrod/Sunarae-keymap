# Sunarae architecture

The app bundle, input-source ID and IMK connection use `local.inputmethod.Sunarae`, `Sunarae.app` and `local.inputmethod.Sunarae_Connection`. The test probe and pasteboard identifiers also use Sunarae.

`KeyMap` maps macOS physical key positions to QWERTY ASCII. `Composer` sends those keys to the pinned `2noshift` engine. It keeps snapshots only for the current syllable's per-key undo and releases them on commit/reset. It has no comma state, contextual final mappings, timers, device checks, or external settings.

`InputSession` guards the entire operation against reentrant IMK calls. When a later Hangul key or plain Space arrives during a client query or write, it consumes and queues that key with its modifiers and client. It drains those keys in order after the current operation finishes, while keeping the guard raised. Reentrant commit callbacks cannot clear the current composition. A queued plain Space is inserted even if the preceding queued key already ended composition. Shortcuts and other app-owned keys retain their original events; keys arriving during an explicit ABC switch are not queued. This reentry queue uses no timer, synthetic event, or event-loop wait.

All clients use standard marked composition. `TextClient` exposes only the client identity, marked range, attributed marked updates and final insertion. There is no document-access capability check, selected-range query, substring read, explicit document replacement, or bundle-ID exception. Ghostty uses the same path as every other app.

`InputSession` sends `NSAttributedString` with zero underline and a clear background; `IMKClient` requests a zero-length selection at the end of that string. In the 2026-10-10 live comparison, plain `String` input produced a full-syllable selection despite the requested caret, while explicit attributes preserved the requested caret in the native client and removed the persistent selection in ZenNotes. WebKit still showed transient selections during composition updates, so these attributes do not establish that every selection popup is gone.

The session commits completed syllables with `insertText` and updates only the current marked text. Both operations use `NSNotFound` for the replacement location, leaving placement to the app's input context. Backspace restores the composer's previous key state; an empty marked update deletes the final composing jamo. Once there is no composition, Backspace belongs to the app. The input method retains no committed-text deletion history.

A different client resets the local composition. When a client has reported a marked range and later reports none, the session drops that composition instead of restoring cancelled text. Clients that never report a marked range can still compose. This check reads only the marked range; it does not retry or inspect document text. IMK commit/deactivation and mouse events end the current composition.

Enter, Space, Tab, punctuation, navigation and modified shortcuts commit once and pass their original events to the app. The input method does not synthesize Enter, insert a newline, or impose a timing delay. Editors may still treat Enter as part of composition. The earlier WebKit/CodeMirror comparison did not continue a list with marked input, while ZenNotes did. These are client compatibility limits, not a reason to restore direct replacement.

Version 0.6.0 (25) removes `TextDelivery`, document-range recovery, delayed key retries, direct Space insertion and committed-text deletion. The short synchronous reentry queue remains because a client call can deliver a later Hangul key before the current update finishes. Existing direct-delivery verification documents describe historical versions through 0.5.5, not the current architecture.

The 2026-10-10 production-build checks passed 265,515 composition/session assertions, menu and shortcut checks, seven packaging checks, and the signed sandbox self-check. The web fixture also passed its 16 editor-command checks; those use scripted editor operations and do not replace live IME tests.

Live keys with a temporary 0.6.0 installation produced these results:

- Native NSTextView: `rkk → 까`, zero-length selection after marked updates, three Backspaces removing the three composing keys, then `tjfrul → 설계` and a single Enter producing a newline.
- SilverBullet 2.12.0 desktop app: typing `- 뭔가 적고` and pressing Enter once created the next empty list item. A second run with Enter immediately after typing also passed, as did `설계`, `걸로`, and 30 repeated `ㄹ` keys followed by 30 Backspaces and `까` plus Enter.
- ZenNotes 2.66.0 in its existing Vim insert mode: `rkk → 까` left a caret after the syllable without a selection popup, and one Enter continued the list. The app still drew a composition underline. The earlier popup could not be reproduced in the comparison, so this does not prove all popup triggers are fixed.
- WKWebView/CodeMirror fixture: the short `rkk` plus Enter run produced `- 까\n\n`, without a new list marker. After the longer repeated-deletion run, ordinary and Vim modes preserved the following word; Enter also continued those lists. Thus list handling can differ with the editor mode and event timing. Transient DOM selections still occurred while marked text changed.

The temporary comparison ended by restoring 0.5.5 and checking its binary and live input. The user then requested a permanent 0.6.0 installation. That installation matched the built binary and passed a native input check; the user has since reported better typing. No 0.6.0 release was published by these checks.

`InputSettings` stores an opt-in Boolean for bare Escape / Control-[ to select ABC. `InputSession` finishes composition, calls the source-selection callback while its reentrancy guard is active, then passes the original event to the client. `InputSource` selects an already enabled ABC through TIS; it never enables or registers a source. The sandbox permits only the local `com.apple.tsm.portname` lookup needed to notify the focused editor. No network, Accessibility or Input Monitoring access is added.

Unlike the withdrawn 0.3.1, there is no pass-through latch, internal English mode, or current-source query in key handling. A later key delivered to the same session can compose Korean without waiting for an activation callback. This avoids making an input-source cache query a condition for Korean input. It does not impose ordering on events already queued by another process; rapid exit-and-command sequences still need live checks.

`GlobalHotKey` registers one chosen chord with Carbon's `RegisterEventHotKey`, including press and release handlers. A repeat gate allows one switch per press. Registration uses the exclusive option, checks enabled symbolic system shortcuts, and claims the new key before releasing the previous key. A failed replacement leaves the previous registration and stored preference intact. It uses no event tap, synthetic key event, or global key monitor.

`ShortcutManager` restores the stored choice at process startup and persists changes only after registration succeeds. Its backend and toggle action can be replaced in tests, so automated checks never claim real hotkeys or change input sources. A toggle reads the current TIS source once, chooses ABC when Sunarae is selected and Sunarae otherwise, commits the active controller before leaving Korean, then selects an already enabled source. This current-source query runs only on the explicit hotkey, never on ordinary typing.

`ShortcutSettingsController` presents an AppKit panel from the IMK menu. It pauses registration while open, records a key only through a local monitor restricted to its own window, and restores the saved choice on close. Applying saves a successful registration; cancelling leaves the preference alone. Only a key code and supported modifier mask are persisted. Modifier-only and Fn shortcuts are excluded; bare function keys and Control/Option/Command chords are supported. Esc and Control-[ remain reserved for the existing one-way exit action.

Caps Lock uses macOS's native input-source switching, enabled for this input method by the existing `TICapsLockLanguageSwitchCapable` bundle key. The settings panel explains how to enable it and opens the Keyboard settings pane. It does not register Caps Lock as a Carbon hotkey, change system preferences, or add key monitoring. The system chooses the Latin/non-Latin source pair and handles long presses for uppercase; this is separate from the configurable ABC/Sunarae hotkey. See [Apple's bundle-key documentation](https://developer.apple.com/documentation/bundleresources/information-property-list/ticapslocklanguageswitchcapable) and [input-source settings guide](https://support.apple.com/ko-kr/guide/mac-help/-mchl84525d76/mac).

The input method must be running to receive its global hotkey, so users select Sunarae once after login. No login item, helper process, additional entitlement, Accessibility or Input Monitoring permission is added. Remapping tools and firmware can intercept keys before Carbon; registration cannot detect all such conflicts.

The C vendor contains only the former upstream base plus the Sunarae table, repeated-vowel branch, and one snapshot helper. The old direct-final and reverse-order patches are gone. The reference data and engine source revisions are pinned in `spec/sources.json`; normal builds are offline.

Installation validates the incoming ID and reads any prior identity from the installed Sunarae bundle's executable, controller, connection and TIS metadata. It never stores a list of historical names. A recognized prior ID is disabled and replaced; registration failure restores the prior files and enabled state. Changing the ID creates a new settings domain with defaults; it does not copy the old settings container.

`make package` builds a scripts-only .pkg for macOS Installer's current-user home domain. Its bundled postinstall calls the same staged installer with `--switch-to-abc`. It rejects root execution and clears the test-only destination override. No separate installer app, login item, helper process, or admin install is used. The installer checks that ABC switching has completed and checks again before stopping the installed input method. The .pkg is unsigned; input-method approval and Gatekeeper decisions stay with the user.

The installer aborts before moving bundles if the current-source query fails or returns an empty/unknown identifier. The registration helper also refuses to disable sources when it cannot identify the current source. `Diagnose.command` reads build/installed versions, verifies signatures, and queries source state without executing the input method or changing registration. It does not read typed text, documents, or the clipboard.

After replacing an input method, open client apps can retain a broken connection even when registration and the new server look healthy. The 0.3.1 rollback recovered in the probe before Codex/Chrome recovered after restart. Do not report installation or a probe result as proof that an existing client works; verify it after reconnecting or restarting that client.

Builds prepare the entire distribution in a temporary directory beside `dist`. They compile and verify both the input method and registration helper before replacing `dist`. Publication failure restores the previous directory; failed restoration preserves the backup and reports its path. Each successful build starts with an empty distribution, so removed resources do not survive in later builds. Packaging checks use isolated directories and stub registration, never the user's real input-source settings.

## Review on 2026-10-11

The review covered the Swift input path, settings and shortcuts, build/install scripts, tests, and the local libhangul changes. Cleanup removed the unread `CompositionUpdate.preedit` result (and its extra string conversion on each key), the test-only `Composer.isEmpty` accessor, an unread test counter, and the unused `--check-server` mode. The session now keeps its composer private; tests read `markedText`. The probe no longer compiles or links the composition engine, since it sends real keys through the installed input method. The upstream library boundary and the synchronous reentry queue remain in place.

`make check` passed 265,515 assertions, menu and shortcut checks, seven packaging checks, and the signed sandbox self-check. `make probe` also passed. The cleanup changes no composition rules or text-delivery calls. At the user's later request, commit `dfbb386` was installed as 0.6.0 (25). The installed binary matched the build and passed live native checks for `까`, three Backspaces, `설계`, one Enter, and `걸로 까`; marked updates left a zero-length selection. The first attempt typed Latin letters while the probe was inactive. Clicking the probe directly activated it, after which the input checks passed.

Two fault-injection checks identified limits for further work. These checks call the session directly with isolated NSTextViews; they do not show that a real app produces these sequences:

- **An inconsistent marked-range reply can discard a composing syllable.** Type `tj` (`서`), return `NSNotFound` for the next marked-range read while the view still holds marked text, then type `frul`. The result is `ㄹ계`; with accurate replies it is `설계`. The current cancellation guard treats that reply as a cancelled composition. Ignoring it would fail the existing tests that prevent cancelled text from returning. Before changing this guard, capture the affected app's marked-range and commit/cancel sequence in the isolated probe. Do not assume that a missing range means a transport failure or add blind retries.
- **A nested Backspace can run before the active marked update.** Type `r` (`ㄱ`), then `k`; immediately before the client applies the new `가` mark, deliver Backspace through a synchronous callback and let the view handle the returned event. The final text is `가`; an ordinary Backspace after the update correctly leaves `ㄱ`. Only letters and plain Space currently join the reentry queue. If a live trace confirms nested editing keys, test their order together with Enter, shortcuts, client changes and cancellation before extending that queue. Do not consume app-owned commands without a way to preserve their effect.

App-specific Enter/list handling remains a separate compatibility item, as recorded above. Keep the native, SilverBullet, ZenNotes and WebKit checks when text delivery next changes. These limits call for targeted evidence, not a return to committed-character replacement.

The later release review added 78 editing assertions across eight final-consonant carry cases: ordinary and compound finals, repeated and shifted tense finals, compound vowels, and Sunarae initial replacement. Each case checks deletion of only the current syllable, preservation of the committed prefix, and new input after deletion. The full `make check` passed 265,593 assertions, menu and shortcut checks, seven packaging checks, and the signed sandbox self-check. No production code changed in this review.

Two further improvements are worth separating from the composition work:

- **Identify installed builds.** The pre-cleanup and cleanup executables have different SHA-256 hashes but both report 0.6.0 (25). Increase the build number for a new install candidate, and consider embedding the source revision in the bundle and showing it in `diagnose.sh`. This would make installation checks and bug reports clearer without recording typed text.
- **Limit shortcut suspension to recording.** `ShortcutSettingsController.show()` suspends the global hotkey until the panel closes. `windowDidResignKey` stops recording but does not restore the hotkey, so leaving the panel open while returning to another app keeps the configured shortcut unavailable. Restrict suspension to the actual recording interval, restore on cancellation or loss of focus, and check registration failures before changing this behavior. The current tests cover the manager's suspend/restore calls, not the panel's full lifecycle.

GitHub's latest public release at review time was `v0.5.5`. Although `dfbb386` is a cleanup, the next release also includes `d1de14e`'s switch to attributed marked composition. Its release notes should describe that change and the app-dependent Enter behavior, rather than label the whole release as a refactor.
