# 0.2.2 입력 시작과 범위 처리

사용자는 0.2.1에서 SilverBullet의 Enter 문제가 해결됐다고 확인한 뒤, Codex와 타이핑웍스에서는 가끔 키를 눌러도 글자가 전혀 나타나지 않는다고 보고했다.

## 확인한 사실과 아직 남은 확인

- 실행 중인 0.2.1 프로세스의 3초 표본은 정상 이벤트 대기 상태였다. 이 표본을 얻었을 때 선택한 입력기는 기본 두벌식이었으므로, 장애 순간의 교착 상태를 배제하는 증거는 아니다.
- 두꺼비에 한정한 시스템 기록에서 보고 시점 전후의 `Inserting text` 호출을 확인했다. 커서 조회 후 새 입력 경로로 돌아가는 호출도 반복됐다. 이 기록에는 실제 문자열이나 범위 값이 없으므로 앱이 삽입을 받아들였는지까지 알 수 없다.
- 0.2.1은 새 조합의 첫 글자도 `selectedRange`를 명시해 삽입했다. 입력창이 초기화됐지만 앱의 범위 정보가 오래된 경우, 유효하지 않은 교체 요청을 반복할 수 있다.
- 설치된 Chrome 152.0.7977.77과 Codex에 포함된 Chrome Framework 152.0.7977.83을 확인했다. [Chromium 152.0.7977.77의 insertText 구현](https://chromium.googlesource.com/chromium/src/+/refs/tags/152.0.7977.77/content/app_shim_remote_cocoa/render_widget_host_view_cocoa.mm#2705)은 `NSNotFound` 삽입을 키 처리 뒤로 모으고, 명시한 범위의 삽입은 별도 `ImeCommitText` 호출로 보낸다. 두 요청을 동등하다고 가정할 수 없다. 이 차이만으로 실제 장애 원인을 확정하지는 않는다.

## 수정

새 글자는 `NSNotFound` 범위로 현재 선택 위치에 넣는다. 앱이 전에 알려 준 범위를 새 삽입의 목적지로 사용하지 않는다.

다음 키를 처리할 때 첫 글자의 위치를 확인한다. 아직 위치를 확인하지 않은 첫 삽입에 한해서, 현재 커서 바로 앞의 글자가 방금 보낸 글자와 정확히 같은지 확인하고 범위를 정한다. 이후에는 원래 위치와 문자열이 모두 맞아야 교체한다. 다른 곳의 문자열을 검색하지 않는다. 클릭, 방향키, 입력기 전환, 클라이언트 변경은 내부 조합을 끝낸다.

두겹이 조합과 대체 시프트는 변경하지 않았다. 일반 텍스트 경로에서는 마지막 글자가 이미 문서에 있고 Enter가 추가 삽입 없이 앱에 전달된다. 입력 내용 기록, 전역 키 감시, 네트워크 기능은 추가하지 않았다.

## 검사

`Tests/main.swift`의 실제 NSTextView 어댑터에 오래된 선택 범위 응답과 범위 밖 삽입 거부 조건을 넣었다. 이 조건은 앱과 렌더러 사이의 지연을 모사한 것으로, 실제 Codex/Chrome의 장애를 자동 재현한 것은 아니다.

- 수정 전: 새 글자의 삽입 누락을 포함해 2개 검사 실패.
- 수정 후: 11,921개 검사 통과. 오래된 범위에서 첫 글자 삽입 후 `안녕하세요` 조합, 오래된 0 위치와 이모지 뒤 삽입, 같은 입력창 초기화 후 재입력을 포함한다.
- 기존 Enter 전달, 선택 영역 교체, 커서 이동, 외부 편집, 앱 전환, Backspace와 조합 검사를 함께 통과했다.
- 앱 빌드와 서명 검증 통과. `--self-check`: `composition_ok=true network_blocked=true errno=1`.
- 기존 설치 경로에 0.2.2(6)를 등록했고, 두꺼비 입력 소스의 활성화 상태를 유지했다. 설치 시 선택 중인 기본 두벌식을 바꾸지 않았다.

설치 후 사용자는 입력이 어느 정도 잘 동작하지만 약한 버벅임이 느껴진다고 보고했다. 간헐적인 입력 중단이 완전히 사라졌다는 확인은 아니다. Codex UI 자동 조작은 컴퓨터 사용 도구가 허용하지 않았으며, 이를 다른 방식으로 우회하지 않았다.

기존 0.2.1 앱과 소스는 `build/backups/0.2.1`에 보관했다. 다른 입력기를 선택한 뒤 `./scripts/install.sh "$PWD/build/backups/0.2.1" --register-only`로 복원할 수 있다.
