# 0.2.4 쉼표 대체 시프트

오른손 새끼손가락으로 누르던 `;`의 부담을 옮기기 위해 대체 시프트를 `,`로 바꿨다. 키보드나 펌웨어 설정 없이 입력기 안에서 처리한다. `;`는 일반 세미콜론이며 Shift+`,`는 `<`를 입력한다.

첫 쉼표에서 기존 대체 시프트 규칙을 즉시 적용한다. 다음 입력도 쉼표면 변환을 취소하고 원래 글자 뒤에 쉼표 하나를 넣는다. `값,, → 값,`, `닭,, → 닭,`, `생각,, → 생각,`처럼 쓴다. 시간 제한이나 입력 대기는 없다. 변환할 글자가 없으면 쉼표 한 번을 그대로 입력한다. 이 경우 두 번 누르면 쉼표도 두 개다.

## 구현

Composer는 첫 쉼표 전의 조합 상태를 보관한다. `값 → 갑ㅆ`처럼 글자가 갈라지면 앞 글자도 다음 입력까지 교체 범위에 포함한다. 결과는 즉시 앱에 표시하며 일반 텍스트 경로에서는 marked text를 만들지 않는다.

- 두 번째 쉼표: 원래 글자와 쉼표로 전체 범위를 교체하고 상태를 비운다.
- Backspace: 변환 전 조합과 이전 Backspace 상태를 복원한다.
- 다음 한글: 앞 글자를 조합에서 분리하고 이어서 입력한다.
- Enter·Space·방향키·단축키·클릭·입력기 전환: 기존 확정 경로를 사용한다. 일반 텍스트 경로에서 Enter는 추가 삽입 없이 앱으로 간다.
- 커서·문서 내용·입력창 변경: 기존 범위 검사로 상태를 버린다. 이전 글자를 복원하지 않는다.

InputSession의 전달·범위 검사 코드는 그대로이며 쉼표 위치와 Shift+쉼표 매핑만 추가했다. 결합표와 한글 변환 규칙도 그대로다.

## 검사와 설치

- `./scripts/test.sh`: 12,736개 검사, 실패 0개. 결과: `build/tests-comma-shift.txt`.
- 현대 한글 11,172자, 정순·역순 받침 경계, 기존 편집 검사를 유지했다.
- 각 대체 시프트 규칙과 분리되는 받침 전체를 확인했다. 단축키로 넣은 겹받침, 역순 겹받침, 앞에 이모지와 다른 글자가 있는 경우도 검사했다.
- 실제 NSTextView에서 일반 텍스트 및 marked text 경로의 즉시 표시, 쉼표 복원, Backspace, 후속 입력, Enter 전달을 확인했다.
- 커서 이동, 같은 위치의 다른 글자로 교체, 입력창 초기화, 다른 입력창으로 이동한 뒤의 쉼표가 이전 글자를 복원하지 않는지 검사했다.
- `./scripts/build.sh`: 빌드·코드 서명·Info.plist 검사 통과. 결과: `build/build-0.2.4.txt`.
- 서명된 앱의 기존 자체 검사: `composition_ok=true network_blocked=true errno=1`.
- 기존 설치를 0.2.4(8)로 바꾸고 선택한 입력 소스를 dukkeobi로 복원했다. 설치 파일과 빌드의 실행 파일 일치 및 설치 앱 서명을 확인했다.

이는 조합 코드와 실제 NSTextView 편집 검증이다. 업데이트 후 SilverBullet·Codex·타이핑웍스에서 물리 키 입력부터 화면까지의 전체 동작은 아직 확인하지 않았다. 손가락 피로 감소도 실제 사용으로 확인해야 한다.

기존 앱과 주요 소스·검사는 `build/backups/0.2.3`에 보관했다.
