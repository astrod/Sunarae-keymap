# 0.2.6 쉼표 자동 반복과 편집 검사

대체 시프트 키를 오래 누르면 macOS가 보내는 반복 이벤트가 두 번째 쉼표로 처리되어 변환을 되돌리던 동작을 수정했다. 초성·모음·받침 규칙과 앱에 글자를 전달하는 방식은 0.2.5와 같다.

## 쉼표 자동 반복

- InputController가 `event.isARepeat`를 InputSession에 전달한다.
- 쉼표 변환 직후의 반복은 소비하되 글자를 다시 보내지 않는다. 예: `ㄱ` 뒤에 쉼표를 길게 눌러도 `ㄲ`을 유지한다.
- 실제로 키를 떼었다 다시 누르면 기존처럼 `ㄱ,`로 복원한다. 이후의 반복 쉼표는 일반 문장부호다.
- 현재 변환이 없으면 반복으로 새 대체 시프트를 시작하지 않고 일반 쉼표로 처리한다.
- 커서나 입력창이 바뀌었으면 이전 변환을 근거로 반복을 무시하지 않는다.
- Shift+쉼표, Backspace, 다른 키의 기존 동작과 반복을 유지한다. 타이머나 대기 시간을 추가하지 않았다.

## AppKit 검사

`./scripts/test.sh`로 실제 NSTextView와 함께 검사했다.

- 수정 전: 13,076개 검사 중 234개 실패. 자동 반복으로 변환이 풀리거나 쉼표가 누적되는 동작을 재현했다.
- 수정 후: **13,076개 검사 모두 통과**.
- 대체 시프트의 모든 변환·분리 경우를 일반 텍스트 및 marked text 경로에서 검사했다.
- 별도 이름의 pasteboard에 고정 예문을 넣고 AppKit의 `readSelection(from:)`를 실행했다. 사용자 일반 클립보드는 사용하지 않았다.
- 실제 UndoManager로 붙여넣기 취소·복원, 이모지 뒤 한글 입력, 전체 선택 후 교체·취소·복원을 검사했다. 검사에서는 작업별 undo 그룹을 명시했다. 모든 앱의 기본 undo 묶음이 같다는 뜻은 아니다.

기록: `build/tests-before-0.2.6.txt`, `build/tests-after-0.2.6.txt`.

## CodeMirror 검사

전용 InputProbe 앱의 로컬 WKWebView에서 **16개 검사 모두 통과**했다. 일반 모드와 Vim 모드에서 각각 다음 8개를 검사했다.

1. `- 어렵다` 뒤 Enter가 다음 글머리표를 만든다.
2. 그 뒤 고정 예문과 이모지를 붙여넣는다.
3. 붙여넣기를 실행 취소한다.
4. 다시 실행해 복원한다.
5. 이모지 뒤 `ㄱ → 가`를 범위 교체로 입력한다.
6. 문서 전체를 교체한 뒤 실행 취소한다.
7. 문서 교체를 다시 실행한다.
8. 같은 편집기를 비운 뒤 `ㄴ → 나`를 입력한다.

붙여넣기는 고정 DataTransfer를 담은 ClipboardEvent로 실제 편집기의 paste 처리에 전달했다. 실행 취소·다시 실행은 CodeMirror의 history 명령을 사용하고, 반환값과 결과 문서를 모두 확인했다. 실제 키보드나 시스템 IME를 통과한 검사는 아니다. 이 결과를 Codex·SilverBullet 전체 앱의 동작 보장으로 해석하지 않는다.

초기 검사 환경에는 CodeMirror state 6.6.0과 6.7.4가 함께 설치되어 undo 검사가 실패했다. commands를 SilverBullet 2.10.0 잠금 파일과 같은 6.10.3으로 고정하고, state·view가 하나의 버전을 사용하도록 검사 환경의 의존성을 정리했다. 제품 앱에는 JavaScript 의존성을 넣지 않았고 사용자 앱은 바꾸지 않았다.

검사 소스: `Tests/WebProbe/editor.js`. 결과: [편집 검사](verification/0.2.6-editor.json).

## 실제 입력 시간

0.2.6 소스를 복사한 임시 진단 빌드에서 0.2.4와 같은 측정기를 사용한다. 입력 내용·키 코드·문서 범위·앱 식별자는 저장하지 않고 처리 시간과 호출 수 통계만 로컬에 쓴다. 수집은 첫 입력부터 최대 120초 또는 5,000건이며 진단 빌드에는 10분의 유효 기한이 있다. 일반 배포 소스에는 측정 코드를 넣지 않는다.

ChatGPT에서 입력한 338건의 전체 키 처리 시간은 평균 3.016ms, P95 5.265ms, 최대 6.611ms였다. 16.7ms를 넘긴 표본은 없었다. 이전 측정과 조건을 통제하지 않았으므로 최적화 효과의 크기를 확정하지 않는다. [측정 상세](LATENCY-0.2.6.md)에 이전 값과 범위를 함께 기록했다.

## 설치 확인

일반 0.2.6(10)의 빌드·서명·자체 검사를 통과했다. 진단 측정이 자동 종료된 뒤 일반 앱을 설치하고 입력 소스를 dukkeobi로 복원했다. 설치 앱에는 진단 plist 키가 없고 실행 파일은 dist 빌드와 같다. 자체 검사 결과는 `composition_ok=true network_blocked=true errno=1`이다.

이전 0.2.5 앱·소스·검사·스크립트는 `build/backups/0.2.5`에 보관했다.
