# 0.2.7 U 받침 단축키

초성과 모음이 있고 받침이 비어 있을 때, Shift 없이 U를 누르면 ㅀ을 넣는다. `시 + U → 싫`, `이 + U → 잃`, `끄 + U → 끓`, `오 + U → 옳`로 쓴다. 두겹이 공식 기본형에 없는 dukkeobi 확장이다.

일반 모음 자리의 U와 Shift+U는 기존 ㅕ를 유지한다. 모음 결합 우선 검사도 유지한다. 기존 결합표에는 현재 모음 뒤의 ㅕ와 결합하는 쌍이 없다. ㅀ 뒤에 모음을 바로 넣으면 ㄹ을 남기고 ㅎ을 다음 초성으로 넘기며, ㅇ을 넣으면 기존 철자대로 `싫어` 등을 입력한다.

## 검사

- 규칙 추가 전 새 검사를 실행해 13,578개 중 458개 실패를 확인했다.
- 추가 후 **13,578개 검사 모두 통과**했다.
- 표준 두벌식 순서로 현대 한글 11,172자를 만드는 기존 검사도 통과했다.
- 19개 초성 × 21개 모음의 399가지 상태에서 U가 ㅀ을 넣는지 검사했다.
- ㅀ 다음의 모음 21종, 다음 초성 ㅇ, Shift+U, 일반 모음 자리, 기존 받침 뒤 U, 쉼표, Backspace를 검사했다.
- 실제 NSTextView를 사용해 일반 텍스트 경로와 marked text 경로에서 U 입력·지우기·다음 글자·Enter를 검사했다. 일반 텍스트 경로는 Enter에 추가 쓰기 없이 키를 앱에 넘긴다.
- 기존 쉼표 자동 반복과 AppKit 편집 검사를 함께 실행했다.

기록: `build/tests-before-0.2.7.txt`, `build/tests-after-0.2.7.txt`.

이번 검사는 Composer와 InputSession에 고정 키를 전달한 검사다. 모든 사용자 앱에서 실제 키보드를 눌러 확인했다는 뜻은 아니다. 전달 방식과 대체 시프트 코드는 변경하지 않았다. 새로운 대기 시간이나 측정 기능도 추가하지 않았다.

이전 0.2.6 앱·소스·검사·스크립트·README는 `build/backups/0.2.6`에 보관했다.

## 설치 확인

Apple 두벌식으로 잠시 전환해 설치한 뒤 dukkeobi를 다시 선택했다. 설치 앱과 dist 실행 파일의 SHA-256은 모두 `0cd1c141d39f9fb11f393c7509ba399ae99bf7616ee12f0c672b7738721bee1c`다. 설치 앱의 자체 검사 결과는 `composition_ok=true network_blocked=true errno=1`이며, 진단 측정용 plist 키는 없다. 입력 소스 상태는 `registered=true enabled=true selected=true`다.

검사 창을 닫고 원래 앱으로 돌아온 뒤 현재 입력 소스는 ABC였다. 위의 선택 상태는 전용 검사 앱에서 확인한 결과다.
