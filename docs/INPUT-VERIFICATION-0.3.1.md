# 0.3.1 철회 — 2026-10-02

사용 중 순아래가 선택되어 있는데도 영문이 입력된다는 보고를 받아,
Esc / Ctrl+[ → ABC 전환 기능을 제거하고 0.3.0 (14) 코드로 복구했다.
이전의 제한된 시험창 결과만으로 이 기능의 안정성을 판단할 수 없었다.

## 확인한 코드 경로

0.3.1은 ABC 전환 요청 뒤 `passingThroughToABC`를 켜고 한글 조합을 건너뛴다.
활성화 알림이나 현재 입력기 조회 결과에 따라 이 상태를 해제한다.
이 정보가 실제 입력창 상태와 맞지 않으면 한글 키도 그대로 앱에 넘길 수 있다.
설정을 끄는 것만으로 이미 켜진 상태를 해제하지도 않는다.
사용자가 겪은 순간의 알림·조회 결과는 기록하지 않았으므로 정확한 발생 조건은 미확인이다.

## 복구 범위

- 입력기 안의 ABC 전환, 통과 상태, 전환 설정과 메뉴를 제거한다.
- 전환 기능에 추가했던 로컬 Mach 조회 예외도 제거한다.
- 순아래 조합, 마지막 글자 직접 전달, Enter 전달, 연속 삭제 처리는 유지한다.
- 사용자가 설정한 외부 F18 전환은 변경하지 않는다.
- 같은 세션에서 Esc / Ctrl+[ 뒤에도 한글 입력이 이어지는 검사를 추가한다.

복구용 원본 앱은 `build/backups/Sunarae-0.3.0-before-escape-20261002.zip`에 보관한다.
원본 실행 파일의 SHA-256은 다음과 같다.

`0635c05eac003018d19c39a5bafa02832837ff95a0474b68e382672c55ec12ae`

## 복구 확인

사용자가 ABC로 바꾼 뒤 원본 백업 앱을 설치했다. 설치 파일의 버전·서명과
위 해시를 확인했고, 기존 전환 설정도 껐다. 이때 실제 키 입력은 확인하지 않았고,
사용자는 이후에도 영문이 나온다고 보고했다. 파일 복구만으로 입력 복구를 판단한 것은 잘못이었다.

실행 코드·리소스·빌드 스크립트는 전환 기능 전 커밋 `9edfb68`과 같다.
`make check`는 조합·세션·편집 268,282개 검사, 설치·빌드 검사 5개와
서명된 앱의 자체 검사를 통과했다. 자체 검사에서 조합 성공과 네트워크 차단도 확인했다.

## 실제 연결 복구

추가 확인에서는 순아래가 선택되어도 앱 프로세스가 없었다. 설치된 앱을 실행했지만
사용자는 여전히 영문이 나온다고 보고했다. macOS의 `imklaunchagent` 로그에는
`Request for Endpoint Invalid` 오류가 있었고, 별도 시험창에서도 순아래를 선택한 채
`rkk`를 입력하면 그대로 영문이 나왔다. 기본 두벌식 비교 입력도 시험창에서 영문으로 나왔다.

사용자가 시험 시간을 허용한 뒤, 시험창을 기본 두벌식으로 바꾸고 설치된 순아래와
`imklaunchagent` 프로세스를 종료했다. 순아래를 다시 선택하자 macOS가 둘을 새로 실행했다.
앱 파일과 코드는 이 과정에서 바꾸지 않았다. 같은 시험창과 키 입력으로 다음을 확인했다.

- 네이티브 입력창: `rkk` → `까`.
- 같은 입력창: Esc 뒤 `rk`, Ctrl+[ 뒤 `sk` → `까가나`.
- WebKit/CodeMirror: `rkk`, Enter, `rk` → `- 까\n- 가`.
- 웹 입력 기록에 조합 세션이 없고, Enter로 다음 목록이 이어졌다.

시험 기록은 `build/recovery-verification-20261002.jsonl`에 보관했다.
시험창을 종료했고 설치된 0.3.0 앱과 새 연결 서비스가 실행 중임을 확인했다.
이 결과는 교체 뒤 끊어진 연결 상태가 남았음을 뒷받침한다. 원래 0.3.1 사용 중 발생한
영문 입력의 모든 조건을 설명하지는 않는다.

## 남은 문제

시험 후 사용자는 **Codex와 Chrome에서 다시 선택해도 영문이 나온다**고 보고했다.
따라서 전체 복구는 아직 확인하지 못했다. Chrome 프로세스에서 연결 대상 무효 오류가
계속 발생한 것은 확인했지만 로그의 입력기 ID는 비공개 처리되어, 각 오류가 모두 순아래를
뜻한다고 단정할 수 없다. 기존 앱을 완전히 종료하고 다시 열었을 때의 결과를 확인해야 한다.
시험창 통과를 기존 앱의 복구 확인으로 취급하지 않는다.
