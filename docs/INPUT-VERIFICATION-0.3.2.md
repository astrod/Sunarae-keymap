# 두벌식 순아래 0.3.2 (16) — 2026-10-02

## 변경

입력 메뉴의 **Esc / Ctrl+[ 누르면 ABC로 전환** 설정을 다시 추가했다.
기본값은 꺼짐이다. 켜면 현재 글자를 확정하고 TIS에 ABC 선택을 요청한 뒤 원래 키를 앱에 넘긴다.
순아래 조합, 마지막 글자 직접 전달, Enter 목록 잇기, 삭제 처리는 유지했다.
기존 F18 설정은 바꾸지 않았고, 한영 전환 키를 따로 지정하는 기능은 아직 없다.

0.3.1의 `passingThroughToABC` 상태와 현재 입력기 조회는 복원하지 않았다.
전환 뒤 같은 IMK 세션을 다시 써도 활성화 알림 없이 한글을 조합할 수 있다.
전환에 필요한 로컬 `com.apple.tsm.portname` 조회만 허용하며, 네트워크·손쉬운 사용·입력 모니터링 권한은 추가하지 않았다.

## 자동 검사

- `make check`: 조합·세션·편집 **268,581개 검사, 실패 0개**.
- IMK 메뉴 명령과 켜짐·꺼짐 표시 검사 통과.
- 설치·빌드 실패 검사 5개 통과.
- 서명된 앱 자체 검사: `composition_ok=true network_blocked=true errno=1`.
- `make web-probe`: 시험창과 고정 CodeMirror 빌드 성공.

전환 성공·실패, 같은 세션의 한글 재입력, 설정 변경, 확정 순서와 중첩 호출을 확인했다.
자동 검사는 실제 앱의 입력기 연결이나 빠른 이벤트 전달을 대신하지 않는다.

## 설치와 실제 입력

사용자가 ABC 전환 및 시험 시간을 허용했다. 이전 정상 앱은
`build/backups/Sunarae-0.3.0-before-0.3.2.zip`에 보관했다.
설치 파일과 배포 파일의 실행 파일 SHA-256은 같다.

`874b599b82c19b6c8be1b9dc9fee10af989dcf94f76a939f0c2fc003cd818fc5`

설치 직후 순아래를 선택해도 앱 프로세스가 시작되지 않아 첫 시험에서는 `rkk`가 영문으로 나왔다.
시험창을 기본 두벌식으로 바꾸고 기존 `imklaunchagent`를 종료한 뒤 순아래를 다시 선택했다.
macOS가 새 연결 서비스와 설치된 0.3.2 앱을 실행했고, 이후 다음 실제 키 입력을 확인했다.

| 시험 | 결과 |
|---|---|
| 네이티브: `rkk`, Esc, `hj` | `- 까hj` |
| 같은 입력창에서 순아래 재선택, `rk`, Ctrl+[, `hj` | `- 가hj` |
| 웹 Vim: `rkk`, Enter, `rk`, Ctrl+[, `dd` | `- 까\n- 가`를 만든 뒤 둘째 줄을 삭제해 `- 까` |
| 같은 웹 입력창에서 순아래 재선택, `rkk`, Esc, `dd` | `- 까`를 만든 뒤 줄 삭제 |

두 웹 시험은 각 키 사이에 별도의 화면 확인이나 대기 명령을 넣지 않았다.
기록에 조합 세션은 없었다. 모든 속도·앱에서의 이벤트 순서를 보장하는 결과는 아니다.
시험 기록은 마지막 실행만 추려 `build/escape-verification-0.3.2-20261002.jsonl`에 보관했다.

시험창은 종료했고 ABC가 선택된 상태로 끝냈다. 이 Mac의 전환 설정은 켜 두었다.
메뉴 동작은 IMK 명령 검사로 확인했으며 메뉴 막대 UI를 직접 눌러 시험하지는 않았다.

## 남은 확인

Chrome에 로컬 시험 페이지를 여는 동작은 브라우저 도구의 URL 보안 정책이 차단했다.
우회하지 않았으며 Chrome 자동 입력 검사는 하지 않았다. 기존 Codex·Chrome의 한글 입력,
Esc 전환과 한글 복귀는 사용자 확인이 필요하다. 앞선 0.3.1 복구 때는 앱 재시작 후 사용자가 정상 동작을 확인했다.
이번 설치에도 이전 연결이 남을 수 있으므로 시험창 통과와 기존 앱의 확인을 구분한다.
