# 두벌식 순아래 0.4.0 (17) — 2026-10-02

## 변경

입력 메뉴에 **한영 전환 키 설정…**을 추가했다. 기능키 F1–F20 또는
Control·Option·Command를 포함한 조합을 지정해 실제 입력 소스를 ABC ↔ 순아래로 바꾼다.
기본값은 사용 안 함이며, 기존 F18 매핑과 Esc 전환 설정은 바꾸지 않는다.
내부 영문 모드, 전역 키 감시, 추가 권한이나 상주 도우미는 추가하지 않았다.

설정 창에서는 키를 기록하고 적용·취소·해제할 수 있다. 등록 실패는 저장하지 않는다.
설정 창을 열면 이전 단축키를 잠시 해제하고 닫으면 저장된 키를 다시 등록한다.
실행 중인 Sunarae 앱을 Finder에서 열어도 같은 창을 표시한다.

## 자동 검사

- `make check`: 조합·세션·편집 **268,581개 검사, 실패 0개**.
- IMK 메뉴와 새 설정 명령 검사 통과.
- 키 검증, 저장, 등록 실패 시 이전 값 유지, 취소 시 복원, 반복 방지, 전환 방향 검사 통과.
- 설치·빌드 실패 검사 5개 통과.
- 서명된 앱 자체 검사: `composition_ok=true network_blocked=true errno=1`.
- `make probe` 성공. 기존 CodeMirror 시험 자료를 유지했다.

자동 단축키 검사는 등록 대역을 사용한다. 실제 Carbon 이벤트 도착이나 다른 앱의
입력 소스 전환을 검증한 결과는 아니다.

## 설치와 실제 시험

사용자가 ABC 전환 및 시험 시간을 허용했다. 이전 앱은
`build/backups/Sunarae-0.3.2-before-0.4.0.zip`에 보관했다.
설치된 앱과 배포 앱의 실행 파일 SHA-256은 같다.

`65451c11cf887d3e0416d94f79cb3e35c0725ab5da0c6b89c9ef29bbdb5275d3`

설치 직후에는 새 프로세스가 시작되지 않았다. ABC 상태에서 이전 `imklaunchagent`를
종료한 뒤에도 첫 순아래 선택은 영문으로 나왔다. 설치한 앱을 실행하고 시험창에서
입력기를 다시 선택한 뒤 네이티브 `rkk → 까`를 확인했다.

Finder에서 설정 창을 열어 F19 기록·적용과 저장을 확인했다.
자동 UI 도구로 창을 다시 조회했을 때 창이 다시 열려 단축키 등록이 일시 해제되는
상황이 있었다. 이후 창을 닫고 시험해도 자동 도구의 F19는 전환하지 않고 시험창의
keyDown으로 전달됐다. 도구의 입력 경로 때문인지 실제 등록 문제인지는 아직 확정하지 않았다.

실제 키로 전환되는지 요청한 뒤 사용자가 **“오 잘되는듯?”**이라고 답했다.
이후 설정 창과 저장 값을 확인하니 사용자가 F1로 변경한 상태였다.
따라서 사용자 확인은 지정한 키의 동작 확인으로 기록하며, F19 시험 성공으로 기록하지 않는다.
사용 앱과 세부 입력 순서는 받지 않았다.

웹 Enter·Vim 회귀 시험에는 사용자 입력이 섞여 추가 키 전송을 멈추고 시험창을 닫았다.
이 회차를 회귀 시험 통과로 계산하지 않는다. 기존 자동 검사는 통과했고, 조합·문자 전달
코드는 이번 버전에서 바꾸지 않았다.

이후 사용자가 설명의 F18 문구 제거와 전환 키 해제를 요청했다. 실제 설정 창에서
**사용 안 함 → 적용**으로 해제했다. Esc 설정은 켜짐이며 외부 키 매핑은 바꾸지 않았다.

## 0.4.1 (18) 문구 수정

설정 창과 README에서 특정 키 F18에 대한 안내를 일반적인 중복 키 안내로 바꿨다.
키 지원 범위와 전환 코드는 그대로다. `make build`와 서명된 앱 자체 검사를 통과했다.
설치 뒤 실제 설정 창에서 새 문구와 **사용 안 함** 표시를 확인하고 닫았다.
저장 값에서도 전환 키가 없고 Esc 설정은 켜짐인 것을 확인했다.
사용자가 입력 중이라 추가 입력 시험은 하지 않았다.
