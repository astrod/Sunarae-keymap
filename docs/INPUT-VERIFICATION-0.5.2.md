# Sunarae 0.5.2 (21)

## 변경

- 직접 조합 중인 한글 뒤의 일반 공백을 같은 글자 삽입 경로로 전달한다.
  빠른 입력에서 다음 자음이 공백보다 먼저 들어가는 문제를 고친다.
- 조합 중 문서 조회가 일시적으로 실패하거나 커서 응답이 예상과 다르면 한 번 재조회한다.
  실제 글자가 달라졌거나 두 번 모두 확인하지 못하면 기존 조합을 끝낸다.
- 마지막 글자의 조합 표시 없이 입력하는 방식, Enter 전달, 수정키가 붙은 공백,
  조합이 없는 공백과 Vim 일반 모드의 공백 처리는 유지한다.

앱·입력 소스 ID와 순아래 결합 규칙은 그대로다. 기존 설치의 설정을 유지한다.

## 확인 범위

2026-10-05~06 개발 빌드에서 다음을 확인했다. 그 빌드의 버전 표시는
`0.5.1 (20)`이었으며, 같은 입력 코드를 `0.5.2 (21)`로 배포한다.

- 조합·세션·편집 검사 269,120개 통과. IMK 메뉴·단축키, 설치·빌드 검사 7개,
  서명된 앱 자체 검사와 고정 문장 3개의 클라이언트 호출 검사 통과.
- 기존 코드에서 지연된 공백이 `까ㄱ ㅏㄱ`, `각ㄱ ㅘ`, `과ㅇ ㅖ`를 만드는 상황을
  재현했고 수정 후 통과했다.
- 실제 키로 `까 각 과 예`와 Enter를 일반 웹 20회·Vim 삽입 모드 20회 입력했다.
  40회 모두 정확한 글자와 다음 목록 항목을 확인했다. 공백 120개 모두 다음 자음 앞에 들어갔다.
- 네이티브·웹에서 마지막 글자의 선택 표시 없이 입력했다. 웹 반복 시험은 조합 이벤트가
  없었고, Enter는 모두 `keyCode=13`, `isComposing=false`, 편집기 `composing=false`였다.
- 일반 웹·Vim 삽입 모드의 연속 자음 삭제, `까 → 가` 되돌리기,
  Vim 일반 모드의 공백 커서 이동을 확인했다.

자세한 재현·설치 기록은 [재조회 검사](INPUT-VERIFICATION-DIRECT-RETRY.md)와
[공백 순서 검사](INPUT-VERIFICATION-SPACE-ORDER.md)에 있다.
별도 NSTextView·WebKit/CodeMirror 시험창의 결과이며 모든 앱에서의 검증은 아니다.
계속 실패하거나 일관되게 오래된 값을 반환하는 문서 조회는 이번 재조회만으로 해결하지 못한다.

## 릴리즈 빌드 확인

2026-10-06 `make check package`를 다시 실행해 위 자동 검사와 패키지 생성을 통과했다.
패키지를 풀어 버전 `0.5.2 (21)`, arm64 대상, 현재 사용자 설치 설정을 확인했다.
패키지의 앱과 빌드·설치한 앱의 실행 파일 SHA-256은 모두
`54fde4478c9ac768b621188595a1e7ab28e73971722529d08a00069db2ec70be`였다.

이 Mac에 릴리즈 빌드를 설치한 뒤 네이티브·일반 웹·Vim 삽입 모드에서
실제 키로 `까 각 과 예`와 Enter를 다시 확인했다. 웹 두 모드 모두 목록이 이어졌다.
설치 직후 첫 연결에서는 영문이 나와 기본 두벌식과 순아래를 다시 선택한 뒤 확인했다.
시험창을 종료하고 순아래 선택을 복원했으며 설치 경로의 실행 프로세스를 확인했다.
직전 앱 백업은 `build/backups/before-0.5.2.tD0eVk/Sunarae.app`에 보관했다.

## 배포 파일

- `Sunarae-0.5.2-arm64.pkg`: macOS 13 이상 Apple Silicon용 현재 사용자 설치 파일.
- `Sunarae-0.5.2-source.zip`: 릴리즈 커밋의 앱·libhangul 소스, 검사, 빌드 스크립트와 라이선스.
- `SHA256SUMS.txt`: 위 두 파일의 SHA-256.

앱은 로컬 ad-hoc 서명을 사용한다. 설치 파일은 Developer ID 서명·공증을 받지 않았다.
