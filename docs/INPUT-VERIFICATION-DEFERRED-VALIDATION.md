# 보류 입력 취소 전 재확인 검사

검사일: 2026-10-10. 기준 소스: `v0.5.4` (`51f1b91`). 수정본은 0.5.5 (24)이며, 설치와 사용 확인을 거쳐 릴리즈 대상으로 정했다.

## 재현한 문제

글자 조회가 두 번 실패하면 0.5.4는 키를 보류한다. 다음 복구 검사에서 실제 커서는 그대로인데 이전 위치를 두 번 답하면, 입력기는 문서가 바뀌었다고 판단해 조합 상태와 보류 키를 지웠다.

실제 NSTextView에 고정 문자열을 입력하고 조회 응답만 바꿨다. 문서와 실제 선택 범위는 움직이지 않았다.

| 입력 결과 | 0.5.4의 조회 실패 후 오래된 커서 응답 | 수정 후 |
|---|---|---|
| 걸로 | 거로 | 걸로 |
| 설계 | 서계 | 설계 |
| 까 | 가 | 까 |
| 각 | 가 | 각 |
| 과 | 고 | 과 |
| 예 | 여 | 예 |

## 수정

- 보류 키를 처리할 때 글자·커서 응답이 다르면 원래 위치와 조합 상태를 남겨 두고 한 번 더 확인한다. 확인 결과가 맞으면 키를 순서대로 처리한다.
- 첫 보류 키뿐 아니라 뒤에 쌓인 키에도 적용한다. Enter·확정·마지막 재시도에서 강제로 복구할 때도 같은 검사를 쓴다.
- 재확인 중 글자를 읽지 못하면 키를 남겨 다음 재시도에서 확인한다. 변경 가능성도 함께 기억한다. 끝까지 확인하지 못하면 다른 선택 영역에 보류 키를 새로 삽입하지 않는다.
- 실제 변경을 재확인하면 이전 보류 키를 취소한다. 일반 입력의 조회와 표시 방식은 유지한다.

## 검사 결과

`Tests/RecoveryValidationChecks.swift`를 추가했다. 기존 0.5.4 코드에 새 검사를 적용하면 197건이 실패했고, 수정 후에는 전체 271,060개 검사를 통과했다.

새 검사는 여섯 단어, 네 응답 오류(커서·선택 범위·글자·글자 조회 뒤 커서), 네 복구 시점(예약 실행·다음 키·Enter·마지막 시도), 두 앞부분(빈 문자열·이모지 포함)을 조합한다. 키 여러 개를 복구하다가 응답이 어긋나는 경우, 재확인 응답 누락, 재확인 중 실제 커서 이동도 검사한다.

기존 검사를 통해 실제 커서 이동·선택·문서 교체·문서 비우기, Backspace·Enter·단축키·클라이언트 전환, 중첩 호출 순서, 오래된 예약 작업 무효화, Ghostty의 표준 조합 경로도 확인했다. 직접 입력에서 조합 표시나 선택된 마지막 글자가 생기지 않는 검사를 유지했다.

가짜 시계를 쓰는 회귀 검사 외에, 기본 main-queue 예약을 그대로 쓴 별도 시험도 18/18건을 통과했다. 정상 입력·조회 응답 누락만 있는 경우·누락 뒤 오래된 커서 응답이 오는 경우를 여섯 단어로 비교했다.

일반 입력의 TextClient 호출 결과는 0.5.4와 같았다. 세 고정 입력의 호출 수는 각각 135, 51, 36회다. 이는 호출 횟수 검사이며 실제 앱의 응답 시간 측정은 아니다.

별도 소스 복사본에서 `make check`를 통과했다.

- 규칙 27개 확인, 앱 빌드와 서명 확인.
- 조합·편집 검사 271,060개, 실패 0개.
- IMK 메뉴와 단축키 검사 통과.
- 설치·빌드·패키지 검사 7개 통과. 임시 경로와 등록 대역을 사용했다.
- 앱 자체 검사: `composition_ok=true`, `network_blocked=true`.

로컬 결과는 `tmp/deferred-validation/check.log`, `tmp/deferred-validation/calls-fixed.json`, `tmp/input-feel-audit/composition-fixed.json`에 남겼다. 수정 전후 검사 로그는 `tmp/input-feel-audit/recovery-regression-before.log`와 `recovery-regression-after.log`다. 이 임시 파일들은 Git으로 추적하지 않는다.

## 범위와 남은 확인

재현한 짧은 응답 오류에서 키가 빠지던 문제를 고쳤다. 앱이 재확인에도 계속 같은 오래된 응답을 주면 실제 변경과 구별할 수 없다. 문서 변경 가능성을 끝까지 해소하지 못할 때 이전 입력을 취소하는 제한도 남는다.

사용자의 실제 앱에서 같은 응답 오류가 일어났는지는 확인하지 않았다. 아래 설치 시험은 새 입력기의 기본 동작을 확인한 것이며, 간헐적 오류가 모든 앱에서 사라졌음을 입증하지 않는다.
