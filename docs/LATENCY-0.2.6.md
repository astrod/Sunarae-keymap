# 0.2.6 실제 입력 시간 재측정

사용자는 ChatGPT에서 직접 타이핑했다고 답했다. 데스크톱 앱인지 웹인지는 구분하지 않았다. 첫 입력부터 120초 동안 338건을 수집했다. 입력 내용, 키 코드, 문서 범위, 앱 식별자는 저장하지 않았다.

## 결과

단위: ms. P95는 표본의 95%가 이 값 이하라는 뜻이다.

| 측정 구간 | 건수 | 평균 | P50 | P95 | 최대 |
|---|---:|---:|---:|---:|---:|
| 전체 키 처리 | 338 | 3.016 | 3.796 | 5.265 | 6.611 |
| 글자 쓰기가 있는 처리 | 271 | 3.759 | 4.082 | 5.344 | 6.611 |
| 앱 API 호출 합계 | 338 | 2.984 | 3.758 | 5.222 | 6.565 |
| 한글 조합·Backspace | 290 | 0.008 | 0.007 | 0.014 | 0.105 |
| 글자 전달 | 271 | 3.038 | 3.402 | 4.557 | 5.659 |
| 선택 범위 조회 | 272 | 0.241 | 0.247 | 0.305 | 0.644 |
| 기존 글자 조회 | 220 | 0.501 | 0.477 | 0.608 | 5.857 |
| 문서 접근 지원 조회 | 51 | 0.193 | 0.202 | 0.253 | 0.311 |

전체 처리 338건 중 16.7ms·33.3ms·50ms를 넘은 건은 없었다. marked text 호출도 없었다. 처리 시간 합계의 약 99.0%가 앱 조회·글자 전달 API 안에서 걸렸다. 이는 이번 표본에서의 결과이며, 더 긴 지연이 앞으로 없다는 보장은 아니다.

## 이전 측정과 비교

| 버전 | 건수 | 전체 처리 평균 | P95 | 최대 |
|---|---:|---:|---:|---:|
| 0.2.4 | 144 | 4.557 | 15.094 | 18.826 |
| 0.2.6 | 338 | 3.016 | 5.265 | 6.611 |

이번 측정값은 이전보다 낮다. 다만 이전 앱 이름을 기록하지 않았고 입력 문장·속도·시스템 부하도 같게 맞추지 않았으므로, 그 차이를 전부 최적화 효과로 보거나 일정 비율 빨라졌다고 결론내릴 수 없다. 기본 macOS 두벌식과의 비교도 아니다.

0.2.5에서 앱 호출을 줄인 뒤 처음 실시한 실사용 재측정이다. 0.2.6의 일반 타이핑 경로는 그 최적화를 유지한다. 같은 NSTextView 고정 예문으로 확인한 호출 수는 0.2.5와 0.2.6이 각각 129/69/36회로 완전히 같았다. 쉼표 자동 반복 보호로 일반 입력의 앱 호출이 늘지는 않았다.

## 범위와 측정 종료

IME가 keyDown을 받은 뒤 반환할 때까지를 쟀다. 키보드 스캔·무선 전송·IME 도착 전 대기·앱의 비동기 처리·실제 화면 표시까지는 포함하지 않는다. 측정기 자체의 비용은 포함한다.

이전과 같은 측정기를 사용했으며, 임시 소스 복사본과 진단 앱은 `build/latency-2026-09-07-0.2.6`에 있다. 측정은 120초 후 자동 종료했다. 일반 빌드 0.2.6(10)을 다시 설치했고 진단용 plist 키가 없으며 설치 실행 파일과 dist 빌드의 SHA-256이 같음을 확인했다. 일반 앱은 처리 시간을 기록하지 않는다.
